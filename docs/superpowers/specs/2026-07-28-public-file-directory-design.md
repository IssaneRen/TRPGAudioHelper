# 公共文件目录服务设计

## 目标

在现有服务器上公开 `/home/ubuntu/public_files/`，通过服务器公网 IP 的 TCP `14848` 端口浏览目录和下载文件。图片文件应使用浏览器支持的 MIME 类型直接打开，不强制下载。

## 方案

复用服务器已有 Nginx，新增独立站点配置 `/etc/nginx/sites-available/public-files`，并链接到 `/etc/nginx/sites-enabled/public-files`。该配置只监听 TCP `14848`，不使用域名、HTTPS、反向代理或额外常驻进程。

站点以 `/home/ubuntu/public_files/` 为固定根目录，开启 `autoindex` 并显示本地修改时间和易读文件大小。Nginx 只响应静态文件读取；不提供上传、删除、改名或目录创建接口。图片依赖 Nginx 标准 MIME 类型映射，并且不设置 `Content-Disposition: attachment`。

## 安全边界

- 服务公开、无认证、使用明文 HTTP；任何能连接服务器 `14848` 端口的人都可查看和读取目录中的全部内容。
- Nginx 只能映射固定目录，不暴露父目录。
- 仅给 Nginx worker 补充读取该目录所需的最小权限，不改变无关目录和文件。
- 腾讯云轻量服务器防火墙只新增 TCP `14848` 入站规则，不修改现有端口规则。

## 部署与回滚

部署前检查端口占用、Nginx 配置和目标目录权限。若同名站点配置已存在，先生成带时间戳的备份。写入配置后先运行 `nginx -t`，只有校验通过才 reload Nginx。

回滚时删除站点启用链接，恢复备份配置（若存在），再次执行 `nginx -t` 并 reload。目标目录及其中的文件不随配置回滚删除。

## 验收

1. `http://127.0.0.1:14848/` 返回目录索引。
2. 公网 IP 的 `14848` 端口可访问同一目录索引。
3. 子目录可以继续浏览。
4. JPG、PNG、GIF、WebP 等常见图片响应为对应 `image/*` 类型，且不含强制下载响应头，可在浏览器标签页内打开。
5. Nginx 主站和现有服务不受影响。
